# Languages and translations

The game is written in **French**, its source language, and translated into
**English**. It follows GNOME's standard mechanism: gettext, domain
`gnome-critter` (the `gettext-domain` of `extension/metadata.json` and the
GSettings schema), `po/<language>.po` catalogs compiled into
`locale/<language>/LC_MESSAGES/gnome-critter.mo` by `scripts/build.sh`.

The displayed language is the GNOME session's (`LANGUAGE`, `LANG`
variables…). A language with no catalog falls back to French, as gettext
does.

## Where the text lives

| Text | Mechanism | Translations |
| --- | --- | --- |
| Interface: menus, windows, notifications, log, preferences (`extension/`) | `_()`, `ngettext()` | `po/en.po` |
| Core labels: statistics, sections, foods, toys, accessories, tricks, boxes, the Committee (`core/`) | `N_()` in tables, translated at display time | `po/en.po` |
| Shared achievement library (`core/achievementLibrary.js`) | unmarked data, extracted by `scripts/i18n-data.mjs` | `po/en.po` |
| GSettings schema (summaries, descriptions) | `xgettext` ITS rules | `po/en.po` |
| A pack's text: species name, given names, its own achievements | the `translations` section of `pack.json` | inside the pack |
| Generic given names (packs without names) | one list per language (`GENERIC_NAMES_BY_LANGUAGE`, `core/names.js`) | in the code |

Packs carry their own translations to stay self-contained: a third-party
pack is translated without touching the game's catalog. Format:
`docs/pack-format.md`, "Translations" section.

## Mechanics (`core/i18n.js`)

- `_(msgid)`: translated text.
- `ngettext(singular, plural, n)`: the language's plural form (French: 0 and
  1 are singular; English: only 1 is).
- `N_(msgid)`: marks a text for extraction without translating it. Used for
  tables evaluated when the module is imported, before the language is
  known. Functions translate them at display time: `statLabel`,
  `categoryLabel`, `foodLabel`, `accessoryLabel`, `trickLabel`, `boxLabel`…
- `fmt(template, values)`: replaces named placeholders (`{name}`,
  `{count}`…). The translator can move them within their sentence.
- `setTranslator({ gettext, ngettext, language })`: plugs in the active
  translator. With no argument, it falls back to French. Who plugs it in:
  - the extension, in `enable()`, with `this.gettext` and the language from
    `GLib.get_language_names()`;
  - the preferences, with their own functions;
  - the tests and the review tool, with a `.po` catalog read in JavaScript
    (`tools/review/po.js`).
- `language()`: the displayed language. Used by `formatCount` (thousands
  separator: narrow no-break space in French, comma in English), by
  generic given names, and by the packs' `translations` section.

`buildAchievements` translates the library's text at build time.
Descriptions are translated before `{n}` and `{s}` are rendered.

## Writing a text

- One whole sentence per text, never concatenated fragments.
- Values go through named placeholders: `fmt(_('{name} a éclos.'), { name
  })`. No `` `${name} a éclos.` `` template literal inside `_()`: xgettext
  doesn't extract it and the translator couldn't reorder the sentence.
- Plurals:
  - `fmt(ngettext('{n} pièce', '{n} pièces', n), { n })`, never
    `n > 1 ? 's' : ''`;
  - in the library's series descriptions, `{s}` adds an "s" beyond 1. Each
    language uses it wherever it fits: "Faire {n} repas" becomes "Eat {n}
    meal{s}".
- Titles: invariable appositions, with no gender: "Minou, as de la sieste",
  "Whiskers, nap ace".
- English tone:
  - the Comité becomes "the Committee";
  - the critter is "it";
  - “ ” quotation marks;
  - no space before ": ! ?".
- Proper noun never translated: "Critter" (the source of notifications and
  the top-bar button).

## Workflow

1. Write or edit the text in French, in the code or the library.
2. `scripts/i18n.sh update`:
   - regenerates `po/gnome-critter.pot` (xgettext over `extension/` and
     `core/`, the schema, then the library);
   - merges the result into every catalog in `po/LINGUAS`.

   A new or changed text arrives with an empty translation
   (`--no-fuzzy-matching`). A removed text becomes obsolete (`#~`).
3. Translate `po/en.po` with Poedit, GNOME's translation editor, or a plain
   text editor.
4. `scripts/i18n.sh check`: checks the catalog with `msgfmt --check` and
   shows the translation rate.
5. `npm test` (see "What the tests check").
6. `scripts/build.sh --link` compiles the catalogs. Requires the `gettext`
   package; without `msgfmt`, the build warns and the extension stays in
   French.
7. Try it out:
   - `scripts/dev.sh --lang en` launches the nested session in English (the
     real session isn't touched);
   - `scripts/review.sh`, then the language choice in the review tool's
     header.

## What the tests check (`tests/i18n.test.js`)

- **Catalog**. `po/en.po` must be:
  - up to date with `po/gnome-critter.pot`;
  - fully translated, with no fuzzy entry, with two plural forms;
  - faithful to the French placeholders (aside from `{s}`);
  - free of French-style quotes or spacing.
- **Coverage**. Every literal passed to `_()`, `N_()`, or `ngettext()` in
  `extension/` and `core/` is in the catalog, as is every text in the
  library. No `${}` template literal is passed to these functions.
- **Nothing slips through**. No text-looking literal remains outside these
  functions in the interface: an accent, two words, or a single
  capitalized word. Exceptions:
  - development logs and errors (`console.*`, `logError`, `Error`);
  - "Critter";
  - the library and given names, handled separately.
- **Packs**. Every pack in the repo has a valid, complete `en` section, with
  the same placeholders as the French. `localizePack` falls back to French
  field by field.
- **English rendering**. With the English catalog, expanded achievements and
  the Committee's announcements (achievements, streaks, trophies) no longer
  contain French: no accents, no quotation marks, no small French words.

The tests' JavaScript literal reader (`tests/helpers/jsStrings.js`) is
enough for the repo's code. It isn't a full parser.

## Review tool

The header's language selector is kept in the address (`&lang=en`). It
loads `po/<language>.po`, plugs in the translator, and localizes the packs.
The game's text is then shown in that language: achievements, in-game view,
the Committee, titles, rewards, given names. The tool's own interface stays
in French.

The **Checks** tab then adds:

- **the catalog**: missing or fuzzy translations, different placeholders,
  French typography. Text identical to the French is flagged as "info":
  it's often intentional ("Exploration", "{n} min"), sometimes an
  oversight;
- **per pack**:
  - an incomplete or invalid `translations` section;
  - different placeholders;
  - displayed text left in French;
  - notifications too long in that language.

The usual checks (typography, gendered titles…) still apply to the French.

## Adding a language

1. Add its code:
   - to `po/LINGUAS`;
   - to `LANGUAGES` in `core/i18n.js`;
   - to `LANGUAGE_CHOICES` in `tools/review/app.js`.
2. `scripts/i18n.sh update` creates `po/<code>.po` with every translation
   empty.
3. Translate the catalog.
4. In the code and the packs:
   - a list of given names in `GENERIC_NAMES_BY_LANGUAGE`;
   - a `translations.<code>` section in every pack;
   - if needed, `formatCount`'s thousands separator.
5. Extend `tests/i18n.test.js` to the new language: today it only checks
   English.

## Limits

- Changing language requires restarting GNOME Shell: gettext reads the
  language at startup.
- A language with no catalog shows French.
- Log entries already written stay in the language they were written in.
- The name and description in `extension/metadata.json`, shown by the
  Extensions app, don't go through gettext: they stay in French.
- A third-party pack is only translated if it provides its own
  `translations` section.
