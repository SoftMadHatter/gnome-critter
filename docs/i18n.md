# Langues et traductions

Le jeu est écrit en **français**, sa langue source, et traduit en **anglais**.
Il suit le mécanisme standard de GNOME : gettext, domaine `gnome-critter`
(`gettext-domain` de `extension/metadata.json` et du schéma GSettings),
catalogues `po/<langue>.po` compilés en `locale/<langue>/LC_MESSAGES/gnome-critter.mo`
par `scripts/build.sh`.

La langue affichée est celle de la session GNOME (variables `LANGUAGE`,
`LANG`...). Une langue sans catalogue retombe sur le français, comme le fait
gettext.

## Où vivent les textes

| Textes | Mécanisme | Traductions |
| --- | --- | --- |
| Interface : menus, fenêtres, notifications, journal, préférences (`extension/`) | `_()`, `ngettext()` | `po/en.po` |
| Libellés du cœur : statistiques, rubriques, aliments, jouets, accessoires, tours, boîtes, le Système (`core/`) | `N_()` dans les tables, traduits à l'affichage | `po/en.po` |
| Bibliothèque commune de succès (`core/achievementLibrary.js`) | données sans marqueur, extraites par `scripts/i18n-data.mjs` | `po/en.po` |
| Schéma GSettings (résumés, descriptions) | règles ITS de `xgettext` | `po/en.po` |
| Textes d'un pack : nom de l'espèce, prénoms, succès propres | section `translations` de `pack.json` | dans le pack |
| Prénoms génériques (packs sans prénoms) | une liste par langue (`GENERIC_NAMES_BY_LANGUAGE`, `core/names.js`) | dans le code |

Les packs portent leurs propres traductions pour rester autonomes : un pack
tiers se traduit sans toucher au catalogue du jeu. Format :
`docs/pack-format.md`, section « Traductions ».

## Mécanique (`core/i18n.js`)

- `_(msgid)` : texte traduit.
- `ngettext(singulier, pluriel, n)` : pluriel de la langue (français : 0 et 1
  au singulier ; anglais : 1 seulement).
- `N_(msgid)` : marque un texte pour l'extraction sans le traduire. Sert aux
  tables évaluées à l'import du module, avant que la langue soit connue. Des
  fonctions les traduisent à l'affichage : `statLabel`, `categoryLabel`,
  `foodLabel`, `accessoryLabel`, `trickLabel`, `boxLabel`...
- `fmt(modèle, valeurs)` : remplace les espaces réservés nommés (`{name}`,
  `{count}`...). Le traducteur peut les déplacer dans sa phrase.
- `setTranslator({ gettext, ngettext, language })` : branche le traducteur
  actif. Sans argument, on revient au français. Qui le branche :
  - l'extension, dans `enable()`, avec `this.gettext` et la langue de
    `GLib.get_language_names()` ;
  - les préférences, avec leurs propres fonctions ;
  - les tests et l'outil de revue, avec un catalogue `.po` lu en JavaScript
    (`tools/review/po.js`).
- `language()` : langue affichée. Elle sert à `formatCount` (séparateur de
  milliers : espace fine en français, virgule en anglais), aux prénoms
  génériques et à la section `translations` des packs.

`buildAchievements` traduit les textes de la bibliothèque à la construction.
Les descriptions sont traduites avant le rendu de `{n}` et `{s}`.

## Écrire un texte

- Une phrase entière par texte, jamais de morceaux concaténés.
- Les valeurs passent par des espaces réservés nommés :
  `fmt(_('{name} a éclos.'), { name })`. Pas de gabarit `` `${name} a éclos.` ``
  dans `_()` : xgettext ne l'extrait pas et le traducteur ne pourrait pas
  réordonner la phrase.
- Pluriels :
  - `fmt(ngettext('{n} pièce', '{n} pièces', n), { n })`, jamais
    `n > 1 ? 's' : ''` ;
  - dans les descriptions de séries de la bibliothèque, `{s}` ajoute « s »
    au-delà de 1. Chaque langue l'emploie où il lui convient : « Faire {n}
    repas » devient « Eat {n} meal{s} ».
- Titres : des appositions invariables, sans genre : « Minou, as de la
  sieste », « Whiskers, nap ace ».
- Ton anglais :
  - le Système devient « the System » ;
  - l'animal est « it » ;
  - guillemets “ ” ;
  - pas d'espace avant « : ! ? ».
- Nom propre jamais traduit : « Critter » (source des notifications et
  bouton de la barre supérieure).

## Flux de travail

1. Écrire ou modifier les textes en français, dans le code ou la
   bibliothèque.
2. `scripts/i18n.sh update` :
   - régénère `po/gnome-critter.pot` (xgettext sur `extension/` et `core/`, le
     schéma, puis la bibliothèque) ;
   - fusionne le résultat dans chaque catalogue de `po/LINGUAS`.

   Un texte nouveau ou modifié arrive avec une traduction vide
   (`--no-fuzzy-matching`). Un texte supprimé devient obsolète (`#~`).
3. Traduire `po/en.po` avec Poedit, l'éditeur de traductions de GNOME ou un
   simple éditeur de texte.
4. `scripts/i18n.sh check` : vérifie le catalogue avec `msgfmt --check` et
   affiche le taux de traduction.
5. `npm test` (voir « Ce que vérifient les tests »).
6. `scripts/build.sh --link` compile les catalogues. Il faut le paquet
   `gettext` ; sans `msgfmt`, le build avertit et l'extension reste en
   français.
7. Essayer :
   - `scripts/dev.sh --lang en` lance la session imbriquée en anglais (la
     vraie session n'est pas touchée) ;
   - `scripts/review.sh`, puis le choix de langue dans l'en-tête de l'outil
     de revue.

## Ce que vérifient les tests (`tests/i18n.test.js`)

- **Catalogue**. `po/en.po` doit être :
  - à jour avec `po/gnome-critter.pot` ;
  - entièrement traduit, sans entrée floue, avec deux formes par pluriel ;
  - fidèle aux espaces réservés du français (`{s}` mis à part) ;
  - sans guillemets ni espaces à la française.
- **Couverture**. Chaque littéral passé à `_()`, `N_()` ou `ngettext()` dans
  `extension/` et `core/` est au catalogue, ainsi que chaque texte de la
  bibliothèque. Aucun gabarit `${}` n'est passé à ces fonctions.
- **Rien n'échappe**. Aucun littéral d'allure textuelle ne reste hors de ces
  fonctions dans l'interface : accent, deux mots, ou mot seul à majuscule.
  Exceptions :
  - les journaux et erreurs de développement (`console.*`, `logError`,
    `Error`) ;
  - « Critter » ;
  - la bibliothèque et les prénoms, traités à part.
- **Packs**. Chaque pack du dépôt a une section `en` valide et complète, avec
  les mêmes espaces réservés que le français. `localizePack` retombe champ
  par champ sur le français.
- **Rendu anglais**. Avec le catalogue anglais, les succès développés et les
  annonces du Système (succès, rafales, trophées) ne contiennent plus de
  français : ni accents, ni guillemets, ni petits mots.

Le lecteur de littéraux JavaScript des tests (`tests/helpers/jsStrings.js`)
suffit au code du dépôt. Ce n'est pas un analyseur complet.

## Outil de revue

Le sélecteur de langue de l'en-tête est gardé dans l'adresse (`&lang=en`). Il
charge `po/<langue>.po`, branche le traducteur et localise les packs. Les
textes du jeu s'affichent alors dans cette langue : succès, vue en jeu, le
Système, titres, récompenses, prénoms. L'interface de l'outil reste en
français.

L'onglet **Contrôles** ajoute alors :

- **le catalogue** : traductions manquantes ou floues, espaces réservés
  différents, typographie française. Les textes identiques au français sont
  signalés en « info » : c'est souvent voulu (« Exploration », « {n} min »),
  parfois un oubli ;
- **par pack** :
  - section `translations` incomplète ou invalide ;
  - espaces réservés différents ;
  - textes affichés restés en français ;
  - notifications trop longues dans la langue.

Les contrôles habituels (typographie, titres genrés...) portent toujours sur
le français.

## Ajouter une langue

1. Ajouter son code :
   - à `po/LINGUAS` ;
   - à `LANGUAGES` dans `core/i18n.js` ;
   - à `LANGUAGE_CHOICES` dans `tools/review/app.js`.
2. `scripts/i18n.sh update` crée `po/<code>.po` avec toutes les traductions
   vides.
3. Traduire le catalogue.
4. Dans le code et les packs :
   - une liste de prénoms dans `GENERIC_NAMES_BY_LANGUAGE` ;
   - une section `translations.<code>` dans chaque pack ;
   - si besoin, le séparateur de milliers de `formatCount`.
5. Étendre `tests/i18n.test.js` à la nouvelle langue : il ne vérifie
   aujourd'hui que l'anglais.

## Limites

- Changer de langue demande de relancer GNOME Shell : gettext lit la langue
  au démarrage.
- Une langue sans catalogue affiche le français.
- Les entrées déjà écrites du journal restent dans la langue du moment où
  elles ont été écrites.
- Le nom et la description de `extension/metadata.json`, affichés par
  l'application Extensions, ne passent pas par gettext : ils restent en
  français.
- Un pack tiers n'est traduit que s'il fournit sa section `translations`.
